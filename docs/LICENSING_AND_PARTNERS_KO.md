# 본문·번역본·설교 요약 — 권리 정리와 제휴 연락처

> 판단 참고용 정리입니다. 법률 자문이 아닙니다. 상업 출시 전 지식재산권 변호사 상담을 권장합니다.
> 이 문서의 내용은 `fullstack/` 샘플의 숨김 기능(오늘의 본문, 설교 요약) 설계에 반영되어 있습니다.

## 1. "오늘의 본문" 기능

### 본문 범위(예: 요한복음 3:1~15) 자체
- 저작권은 표현을 보호하고 사실·아이디어는 보호하지 않습니다. "어느 날 어느 장 몇 절"은 사실에 가까워 저작권 보호를 받기 어렵다는 것이 일반적인 시각입니다.
- 다만 한국에는 두 가지 변수가 더 있습니다.
  - **부정경쟁방지법 "성과 도용"**: 타인이 상당한 투자로 만든 성과를 무단으로 영업에 쓰는 행위
  - **데이터베이스제작자 권리**
- 출판사(예: 두란노 『생명의 삶』)의 월간 본문 일정을 체계적·지속적으로 가져와 앱의 핵심 가치로 삼으면, 특히 발행 전후로 일정을 미리 입수해 넣으면 위 주장이 나올 여지가 있습니다.
- 다른 앱이 비슷한 기능을 제공한다는 사실(예: 'QT공동체' 앱 소개 문구)이 제휴 여부가 확인되지 않은 이상 안전하다는 근거가 되지는 않습니다.

### 이 저장소의 설계 (리스크를 줄이는 구조)
- 앱은 출판사 일정을 **제공하지 않습니다.** 사용자가 본문 범위를 직접 입력하거나, 소그룹 리더가 그룹에 본문을 지정합니다. 앱은 입력을 해석(`server/bible/reference.js`)하고 허가된 번역본으로 보여주는 **도구 역할**만 합니다.
- 화면에 "본문 범위는 사용자가 입력합니다. 특정 출판사의 본문 일정·해설은 제공하지 않습니다." 문구를 둡니다.
- 앱 소개나 화면에 "생명의 삶 본문 제공" 같은 표현을 쓰지 않습니다(상표·제휴 오인 소지). 언급해야 한다면 "두란노와 무관함"을 밝히고, 마케팅 전면에 내세우지 않습니다.
- 가장 깔끔한 방법은 출판사와 제휴하거나 이용 허락을 받는 것입니다(아래 연락처 참고).

## 2. 성경 번역본 저작권 (실질적인 리스크)

`fullstack/server/bible/translations.js`의 등록부가 이 표를 그대로 코드로 강제합니다. `licensed` 번역본은 해당 환경변수가 `granted`일 때만 본문을 내보냅니다.

| 번역본 | 권리자 | 상태 | 코드 설정 |
|---|---|---|---|
| 개역한글 | (보호기간 만료로 알려짐) | 사용 가능. 출시 전 현재 상태 재확인 필요 | `open` |
| 개역개정 | 대한성서공회 | 사용 허가 필요 | `LICENSE_RNKSV=granted` |
| 새번역 | 대한성서공회 | 사용 허가 필요 | `LICENSE_RNKV=granted` |
| 우리말성경 (생명의 삶 사용 번역) | 두란노서원 | 사용 허가 필요 | `LICENSE_WOORIMAL=granted` |
| KJV, WEB, BSB | 퍼블릭 도메인 | 사용 가능 (KJV는 영국 내 예외 있음) | `open` |
| NIV | Biblica | 서면 허가 필요 | `LICENSE_NIV=granted` |
| ESV | Crossway | 허가 필요 | `LICENSE_ESV=granted` |

### NIV를 쓰려면
- "500절까지는 허락 없이 인용 가능" 규정은 매일 본문을 보여주는 앱에는 맞지 않습니다. 하루 10~20절씩만 보여줘도 한두 달이면 500절을 넘깁니다.
- Biblica FAQ에 따르면 앱·웹사이트 사용은 가능하지만 서면 허가가 필요합니다. 조건에 따라 Express License 또는 Standard Publishing License를 받습니다.
- **신청 창구**
  - 미국·캐나다 내 상업적 사용: Zondervan (HarperCollins Christian Publishing 허가 요청 양식)
  - 영국·유럽: Hodder & Stoughton
  - 비상업적 사용 및 기타: Biblica (biblica.com/permissions)
- Biblica는 제품이 어느 정도 완성된 뒤 "무엇이 독창적인지"를 포함해 신청하라고 안내합니다. 승인이 쉽지 않고, 비용은 협상에 따라 다릅니다.
- **현실적인 순서:** 처음엔 KJV·WEB·BSB 같은 퍼블릭 도메인 번역본으로 시작하고, 앱이 자리 잡은 뒤 NIV를 신청합니다. Biblica는 일부 본문을 open.bible에서 CC BY-SA로도 제공합니다.

### 본문 데이터 넣는 법
- `fullstack/data/bibles/<id>.json` 형식: `{ "John": { "3": { "16": "..." } } }` (책 이름은 `server/bible/books.js`의 id)
- 지금은 요한복음 3:16 한 절씩만 샘플로 들어 있습니다. 출시 전 전체 퍼블릭 도메인 파일로 교체하세요.

## 3. 설교 요약 (녹음 → 전사 → 요약)

- **구조:** `server/sermons/stt.js`(음성→글) → `server/bible/spoken.js`("요한복음 삼 장 십육 절" → "요한복음 3:16") → `server/sermons/summarize.js`(Claude가 설교 노트 형식으로 요약)
- **STT 선택지:** OpenAI Whisper(구현됨), 네이버 CLOVA Speech, 리턴제로(VITO). 연결 방법은 `stt.js` 주석에 정리했습니다. 한국어 설교라면 실제 설교 몇 편으로 직접 비교한 뒤 고르세요.
- **정확도:** 성경 인명·지명과 신학 용어 목록(`server/sermons/keywords.js`)을 키워드 부스팅에 넣습니다.
- **설교 저작권:** 설교는 설교자의 저작물입니다.
  - 개인이 듣고 요약해서 혼자 보는 것은 문제가 적습니다. 그래서 요약은 기본적으로 **나만 보기**입니다.
  - 다른 사람에게 공유하려면 교회의 동의가 필요합니다. 코드에서는 `churchConsent`가 없으면 공유를 거부합니다.
  - 교회 단위로 가입해 교회가 공식 요약을 배포하는 **B2B 모델**이 이 문제를 가장 깔끔하게 해결하고, 수익 모델로도 좋습니다.
- **비용:** STT와 요약 API 모두 종량제라 설교 한 편당 비용은 크지 않은 편입니다. 다만 요금이 자주 바뀌니 출시 전 최신 요금표로 계산하세요.
