# Daily Thanks — 앱스토어·플레이스토어 출시 계획

> 스토어 정책과 요금은 자주 바뀝니다. 아래 내용은 2025년 기준으로 알려진 내용이니, 계정을 만들고 제출하기 전에 각 공식 페이지에서 한 번 더 확인하세요. 법률·세무 판단은 전문가와 확인하세요.

## 1. 개인사업자 vs 비영리 — 무엇으로 시작할까

### 결론: **개인(개인사업자)으로 지금 바로 시작 → 비영리 단체가 준비되면 앱을 옮기기**

| | 개인 / 개인사업자 | 비영리 (단체·법인) |
|---|---|---|
| 준비 기간 | **며칠** | 수개월 (미국 501(c)(3) 승인, 한국 비영리법인 설립 허가 모두 오래 걸림) |
| Apple 개발자 계정 | 개인 계정, 연 $99. **개인사업자도 Apple에서는 '개인'으로 가입**합니다. | 단체 계정(법인격 + D-U-N-S 번호 필요). 일부 국가의 비영리 단체는 **연회비 면제** 신청 가능 |
| Google Play 계정 | 개인 계정, 1회 $25. **정식 출시 전 테스터 12명 이상이 14일 동안 비공개 테스트**해야 함 | 단체 계정(D-U-N-S 필요). 위 12명·14일 조건이 없음 |
| 스토어에 보이는 판매자 이름 | **본인 실명** (Apple) | 단체 이름 (예: "Daily Thanks Ministry") |
| 장점 | 가장 빠르고 저렴함. 교회·소그룹 지인으로 테스트 조건 충족이 쉬움 | 사명 중심 이미지, 기부금 공제, Google Ad Grants 등 비영리 혜택 |

**이렇게 추천하는 이유**
- "바로 올리고 싶다"는 목표에는 개인 계정이 가장 빠릅니다.
- Google의 12명·14일 비공개 테스트는 오히려 좋은 기회입니다. 교회 소그룹 분들께 먼저 써 달라고 부탁하면, 출시 첫날부터 피드에 감사 글이 채워져 있게 됩니다.
- 비영리 단체는 병행해서 준비하고, 승인되면 앱을 단체 계정으로 이전할 수 있습니다(Apple·Google 모두 앱 이전 기능 있음).

**주의할 점**
- Apple에서 개인 계정의 판매자 이름은 실명으로 노출됩니다.
- **Apple 로그인(Sign in with Apple)을 쓰는 앱을 다른 계정으로 옮길 때**는 사용자 계정 이전 작업이 추가로 필요합니다.
- 처음부터 단체 이름으로 내고 싶고 몇 주를 기다릴 수 있다면, **D-U-N-S 번호(무료, 보통 1–2주)**를 받아 단체 계정으로 시작하는 것도 방법입니다.
  - 미국은 LLC 같은 법인격이 있어야 합니다.
  - 한국은 법인사업자이거나 고유번호증을 가진 비영리단체여야 합니다.

**한국에서 개인사업자 등록이 필요한 시점**
- 무료 앱이면 처음엔 개인 계정만으로도 출시할 수 있습니다.
- 다음 경우에는 사업자 등록과 통신판매업 신고를 검토하세요:
  - 유료 결제·구독·광고 수익이 생길 때
  - 교회 대상 B2B(설교 요약 등)를 시작할 때

## 2. 기술 경로 — 지금 만든 화면을 그대로 앱으로

| 단계 | 내용 |
|---|---|
| 앱 포장 | **Capacitor**로 지금의 HTML/CSS/JS를 iOS·Android 앱으로 감쌉니다. 화면을 다시 만들 필요가 없습니다. |
| 서버 | **Firebase**: 로그인(Apple·Google·전화), Firestore(글·좋아요·저장·신고), Cloud Functions(표현 필터·알림 예약), Cloud Messaging(푸시) |
| 알림 | 알림 안내 화면의 「알림 받기」 버튼에서 iOS 권한 요청(`requestAuthorization`)을 띄웁니다. 정한 시간에 서버가 푸시를 보내고, 그날 이미 쓴 사람은 건너뜁니다. |
| 공유 | 카카오톡: Kakao SDK 피드 템플릿. 인스타그램: 스토리 공유(카드 이미지). |
| 빌드 | iOS는 Mac + Xcode가 필요합니다(또는 클라우드 빌드 서비스). Android는 Android Studio. |

## 3. 심사 통과에 꼭 필요한 것 (체크리스트)

**양쪽 스토어 공통**
- [ ] 개인정보처리방침 URL (한/영)과 이용약관
- [ ] 고객 문의 이메일 또는 웹페이지 (앱 안과 스토어 정보 양쪽에 표시)
- [ ] **앱 안에서 계정 삭제** 기능 (Apple 필수, Google은 웹 삭제 링크도 필요)
- [ ] 사용자 글(UGC) 안전장치: 부적절 표현 필터 ✅, 신고 ✅, 차단 ✅, 운영자 검토 ✅ — **이미 구현되어 있음**
- [ ] 개인정보 수집 내역 신고 (Apple "App Privacy", Google "Data safety")
- [ ] 연령 등급 설문 (사용자 글이 있는 앱이라 보통 12세 이상)

**Apple**
- [ ] Google 로그인을 넣었으므로 **Apple 로그인도 함께 제공** ✅ (화면에 있음)
- [ ] 웹을 감싼 것 이상의 앱다운 기능 (푸시, 기기 공유, 로그인 등). 단순 웹뷰 앱은 반려될 수 있습니다.
- [ ] 스크린샷 6.9인치(필수)와 6.5인치

**Google**
- [ ] (개인 계정) 테스터 12명 이상, 14일 비공개 테스트
- [ ] 최신 Android API 수준으로 빌드

## 4. 일정 (빠르게 가면 약 3–4주)

| 주차 | 할 일 |
|---|---|
| 0주 (오늘) | 계정 형태 결정 → Apple 개발자 계정 · Google Play 계정 가입. 앱 이름과 아이콘 확정. 문의 이메일 만들기 |
| 1주 | Firebase 연결(로그인·글 저장·신고·필터), 계정 삭제, 개인정보처리방침 페이지. Capacitor로 앱 빌드 |
| 2–3주 | **TestFlight(iOS)와 Google 비공개 테스트**를 교회·소그룹 20–30명과 진행 → 피드에 첫 감사 글 채우기, 버그 수정 |
| 3–4주 | 스토어 정보(설명·스크린샷·키워드) 등록 → 심사 제출. Apple 심사는 보통 1–2일 |

## 5. 사람들이 쓰고 싶게 — 출시 준비

1. **빈 피드로 시작하지 않기.** 테스트 기간에 20–30명이 매일 쓰면 출시 첫날 피드가 살아 있습니다.
2. **소그룹 단위로 초대.** 리더 한 명이 「함께 7일」을 열고 링크로 초대합니다. 7일 연속 축하가 자연스럽게 일어납니다.
3. **공유 카드.** 카카오톡·인스타 공유는 영향력 점수에 가장 크게 반영되어, 공유할 이유가 됩니다.
4. **스토어 키워드:** 감사일기, 감사노트, 감사 습관, 기도, 큐티, 소그룹, gratitude journal, thankful
5. **첫 문구:** "매일의 감사가 삶을 풍성하게 합니다 · Daily gratitude makes life richer"
