# 출시 후 수정·업데이트하는 법

## 이 앱은 무엇으로 만들었나요?

- **화면:** HTML · CSS · JavaScript 하나로 만든 웹 앱 (`index.html`, `styles.css`, `app.js`)
- **iOS · Android 앱:** 같은 코드를 **Capacitor**로 감싸서 만들 예정이에요. 코드 하나로 두 스토어에 모두 올라가요.
- **서버:** `fullstack/` (Node). 실제 출시 때는 Firebase로 옮길 수 있어요.

## 바꾸는 방법 3단계 — 위에서부터 가장 쉬워요

### 1) 글과 콘텐츠 → `content/content.json`만 고치면 끝 (심사 없음, 바로 반영)

앱은 켤 때마다 이 파일을 내려받아요. 다음에 앱을 열면 바로 바뀌어요.

| 바꿀 수 있는 것 | 키 |
|---|---|
| 첫 화면 문구 (Give thanks daily. …) | `tagline` |
| 첫 화면 맨 아래 저작권 줄 | `copyright` |
| 오늘의 질문 목록 (언어별) | `dailyQuestions` |
| 공지 한 줄 (한 번만 보여 줌, 기한 설정 가능) | `notice` |
| 운영자가 고른 감사 글 (피드 맨 앞에 보임) | `featuredPosts` |
| 선택 기능을 켜고 끄기 (소그룹 나눔 · 기도 · 설교 노트) | `features` |
| 문의 이메일, 방침·약관 주소 | `supportEmail`, `legalBase` |
| "새 버전으로 업데이트해 주세요" 안내 | `minVersion`, `storeLinks` |

- 파일 안 `_examples`에 예시가 있어요. 복사해서 위로 옮기면 돼요.
- 빈칸(`null`)으로 두면 앱에 들어 있는 기본 글을 써요.
- 인터넷이 안 될 때는 마지막으로 받은 내용을 그대로 보여 줘요.
- 서버 주소: `GET /api/content`. 실제 출시 때는 같은 파일을 Firebase Hosting에 올리거나 Firestore에 넣고, 앱의 `DT_CONTENT_URL`에 그 주소를 적어요.

### 2) 디자인·화면 → 웹 코드 수정

- **보통 방법:** 고친 뒤 새 버전을 스토어에 올려요. 작은 수정은 보통 하루 안에 심사가 끝나요.
- **더 빠른 방법 (선택):** Capacitor의 *라이브 업데이트*(Capgo, Ionic Appflow 등)를 붙이면, HTML·CSS·JS 수정은 심사 없이 바로 내보낼 수 있어요.
  - Apple·Google 모두 앱의 주요 목적을 바꾸지 않는 수정이면 허용해요.
  - 큰 기능 추가는 스토어 업데이트로 내는 게 안전해요.

### 3) 기기 기능 → 스토어 업데이트 필요

홈 화면 위젯, 푸시 알림 설정, 권한 요청, 앱 아이콘, 앱 이름은 앱 자체를 다시 올려야 해요.

## 수정할 때 원칙

- **자주 바뀔 글은 `content.json`에 넣기.** 새로 생기는 공지나 문구도 여기에 키를 하나 추가하는 방식으로 만들어요.
- **작게, 자주.** 한 번에 많이 바꾸지 않으면 심사도 빠르고 문제도 적어요.
- **기능은 스위치로.** 새 기능은 `features`로 꺼 둔 채 출시하고, 준비되면 켜요. 문제가 생기면 바로 꺼요.
- **코드 정리:** 글자는 모두 `app.js`의 `STR`(한·영) + `i18n/es.json`(스페인어)에 모여 있어요. 색과 크기는 `styles.css` 맨 위 변수(`--ink`, `--paper` 등)에서 한 번에 바꿔요.
